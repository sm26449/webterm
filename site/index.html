How it works

The session lives on your machine, not in the browser.

Sessions opened through the agent keep running in tmux on the host when the browser disconnects or the gateway restarts.

Three ways to reach a machine

  • Agent recommended

    One stdlib-only Python file that dials out to the gateway. Nothing listens on your server, and a machine behind NAT works like one with a public IP.

  • SSH

    For machines where you cannot install anything. Host keys are pinned, jump hosts are supported.

  • Telnet

    Switches, PDUs and older gear, reached directly or through an agent inside the network.

Security

Built to sit on the internet.

Whoever gets past the login gets, on every host, the access of the user its agent runs as. So that is where the work goes.

How EverShell is protected →

New in 3.8

Encryption at rest. Stored credentials and every backup are locked with a master key you keep outside the data volume. Session recordings can be encrypted too, compressed first so they stay small, and an erased recording stays erased after a restore. Host backups now stream at any size.

What it covers, and what not →
  • Passkeys and 2FA

    And a fresh second factor before a shell on the hosts you flag.

  • Roles and SSO

    Which hosts each account reaches, and whether it gets a shell. OIDC and SCIM.

  • Signed agent updates

    Agents only run an update signed with your own key.

  • Audit log and backups

    Who did what, from where. Encrypted daily backups that, from 3.8, open only with a master key you keep apart.

Your server, one installer.

Any Linux server with Docker and a domain pointing at it. On a fresh Ubuntu or Debian server, one installer sets up Docker, HTTPS, the firewall, a daily encrypted backup and the master key that protects your data.

Questions

Is it free?

Yes. EverShell is open source under the MIT license, and you run it on your own server. There is no paid tier and no telemetry.

What happens if the gateway goes down?

Sessions on agent hosts keep running in tmux on the host, and are picked up again when the gateway comes back. SSH and telnet sessions live in the gateway, so those end when it restarts.

Does the agent need root?

No. By default it runs as a dedicated, unprivileged webterm user, and you decide what that user may do.

What can I connect?

Linux hosts with Python 3.6 or newer for the agent (older ones get a portable Python), plus anything that speaks SSH or telnet: switches, PDUs, a customer's box.

Can a team use it?

Yes: roles per host or folder, time-bound access, passkeys and 2FA, single sign-on via OIDC and account provisioning via SCIM, and an audit log.

Where is my data?

On your server: sessions, recordings and the database never leave it, and backups are encrypted before they go anywhere. From 3.8, stored credentials and backups are also locked with a master key kept outside the data, and recordings can be encrypted too.
