Install

Your server, your sessions.

EverShell runs as one Docker container behind Traefik, on a server you own. The installer does the rest.

What you need

  • A Linux server with Docker

    Any distribution that runs Docker Compose, with ports 80 and 443 free. The one-command installer below is for a fresh Ubuntu or Debian server; elsewhere, deploy.sh uses the Docker you already have. The published image is amd64; on ARM, build it from source.

  • A domain pointing at it

    For HTTPS. A Cloudflare token adds a wildcard certificate, which covers port-forward subdomains and the agents name. Without one, also point agents.<your domain> at the server.

  • Hosts to reach

    For the agent: Linux with Python 3.6+ and, ideally, tmux. Older hosts get a portable Python. Anything else: SSH or telnet.

Install on Ubuntu or Debian

$ git clone https://github.com/sm26449/webterm.git
$ cd webterm
$ git checkout v3.8.2
$ less install.sh    # it runs as root: read it
$ sudo ./install.sh --domain term.example.com \
      --email you@example.com

It sets up Docker, the stack in /opt/webterm, a Let's Encrypt certificate, the firewall and a daily encrypted backup, then prints the URL and a one-time setup token. From 3.8 it also creates the master key that encrypts your data at rest: copy it off the machine right away, because without it the installation and its backups cannot be opened.

The first ten minutes

01

Create your account

Open the URL, use the setup token, and add a passkey in Settings → Sign-in & 2FA.

02

Add a host

+ Add host gives you a one-line command. Run it on the server: it creates an unprivileged webterm user, and the host comes online.

03

Open a session

Start something, close the tab, and open it again from your phone.

Other ways in

  • Other Linux distributions with Docker

    Copy .env.prod.example to .env, fill it in, run ./deploy.sh.

  • Single sign-on

    With Authentik, bundled or your own: deploy.sh --with-authentik.

  • Many hosts at once

    A group enrollment token: one command, run on every machine.

  • Upgrades

    sudo ./upgrade.sh vX.Y.Z in /opt/webterm, with a rollback if you need it. Once a volume has moved to encryption at rest, the rollback stays within 3.8.

Upgrading to 3.8

From 3.7, a one-way step.

Upgrading to 3.8 changes nothing on its own: with no master key configured, a 3.7 volume runs exactly as before. Adding a key turns on encryption at rest and migrates the volume once, after checking that the old key really opens the database. After that, there is no way back to 3.7 on the same volume.

  • Back up first

    Upgrade, check that 3.8 is healthy, then download a backup from Settings → Backup before you add the key. That backup, restored into a new volume, is the only way back to 3.7.

  • Keep the key off the machine

    Create the key file, copy it to a password manager or a recovery kit, add one line to .env and run sudo ./deploy.sh. Without the key, the installation and every backup it makes cannot be opened.

  • Recordings are a separate choice

    Encrypting session recordings stays off until you turn it on. It needs a protected volume, an SFTP or FTPS destination, a fresh backup and free disk the size of the recordings.
